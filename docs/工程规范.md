# 工程规范

> 《聲律發蒙》幻灯片项目 · 工程约定
> 最后更新：2026-09-11

本文件是项目的**强制约定**。任何新增脚本、内容或版式调整都必须满足这里的要求；
与本文冲突的做法一律视为缺陷。

---

## 1. 目标与边界

把豆瓣日记《聲律發蒙（劉節五卷本）》校訂本制作成可放映的 HTML 幻灯片：

- **原文**：全五卷 106 韻 376 段 → 五个 HTML 文件，竖排右起。
- **注譯**：逐篇推进，尚未开始的内容一律以**占位**形式预留，不产出半成品。

不做的事：不改动原文内容（发现可疑处只标记、不擅改）；不引入第三方 Python 库。

---

```
Shlv/
├── README.md                 项目说明与快速开始

│   ├── fetch_douban_note.py  抓取豆瓣日记 → data/source/*.txt
│   ├── make_slides.py        排版内核（CSS、slide 渲染、原文解析）

│   └── check_deck.py         全量排版质检

│   ├── source/               原始文本（抓取产物，只读）
│   │   └── raw/              抓取时的原始 JSON / HTML 存档
│   └── annotations/          注譯内容 JSON（人工/考据产物）
├── research/
│   ├── 考據報告/              六份考据报告（md）
```

## 3. 环境与依赖

| 项 | 要求 |
|---|---|
| Python | 3.12+（当前 3.14），**只用标准库**，禁止 `pip install` |
| 浏览器 | Google Chrome（`/Applications/Google Chrome.app`），仅用于质检与截图 |
| 网络 | 抓取/考据时需要；`web_fetch` 工具在本机不可用（见 §9.3） |

> 为什么不用 requests/bs4：本机未安装，且标准库已足够；引入依赖会让重建变脆。

## 4. 脚本职责

一个脚本只做一件事；跨脚本复用一律 `import`，不复制代码。

| 脚本 | 职责 | 不负责 |
|---|---|---|
| `paths.py` | 解析仓库内所有路径 | 任何业务逻辑 |
| `fetch_douban_note.py` | 抓取 → 落 `data/source/` | 排版 |
| `make_slides.py` | 解析原文、CSS、单页渲染函数 | 批量编排、质检 |
| `build_deck.py` | 按卷编排（封面+前置+正文） | 单页长什么样 |
| `make_annot.py` | 注譯页组（读 JSON） | 原文页 |
| `render_check.py` | 无头 Chrome 量测/截图（工具库） | 判定合格与否 |
| `check_deck.py` | 依据量测结果判定是否合格 | 修复 |

---

## 5. 路径规范

- **禁止**在脚本里写 `"douban_txt/..."`、`"slides/..."` 这类相对路径。
- 一律从 `paths.py` 取：`BUILD`、`SOURCE`、`ANNOTATIONS`、`REPORTS`、`source_txt()`。
- `paths.ROOT` 由 `__file__` 推导，因此**从任何工作目录调用结果一致**。
- 新增目录时，先在 `paths.py` 声明常量，再在脚本中使用。

## 6. 数据规范

### 6.1 原始文本 `data/source/*.txt`

由 `fetch_douban_note.py` 生成，结构固定为四段：

```
<元信息头：标题/作者/链接/时间/标签/字数…>
============================================================
<正文>
============================================================
<图片清单 / 正文链接清单>
```

解析方（`make_slides.split_front_back`）只取**两个分隔线之间**的正文。

### 6.2 注譯 JSON `data/annotations/*.json`

结构见 `docs/内容与页码约定.md` §3。要点：

- 内容与排版**完全解耦**：改文案不碰代码，改版式不碰文案。
- `text` 字段允许内嵌受限 HTML（`<b>`、`<span class="py">`、`<span class="src">`），
  **不允许**内嵌 `<script>`、行内 `style`。
- 所有考据性内容必须能回溯到 `research/考據報告/`。

## 7. 排版规范

### 7.1 画布

- 固定 **1280×720**（16:9），所有尺寸以 px 写死，靠 `transform: scale()` 适配屏幕。
- 三区绝对定位：页眉（top 44，分隔线 92）、舞台（top 120 / bottom 68）、页脚（bottom 38）。
- 舞台可用高度 **532px**，宽度 1168px。

### 7.2 设计令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` / `--paper2` | `#f6efe1` / `#efe5d2` | 宣纸底色 |
| `--ink` / `--ink-soft` | `#2b2621` / `#5d5347` | 正文墨色 / 次要文字 |
| `--cinnabar` | `#a8331f` | 朱色：韵目、段序、印章、入声标记 |
| `--gold` | `#b08d57` | 描金：边框角饰、分隔线 |
| 正文 | `Songti SC` 30px / `letter-spacing .06em` | 竖排原文 |
| 标题 | `Kaiti SC` | 书名、段序、栏目名 |
| 注释 | `Songti SC` 12.9px / `line-height 1.5` | 注譯页各栏 |

### 7.3 容量表（改动字号前必须重算）

| 区域 | 可用 | 基准字号 | 单列/单栏容量 |
|---|---|---|---|
| 竖排正文列 | 高 532px | 30px | **16 字**（占 509px） |
| 注譯栏（4 栏） | 高 466px | 12.9px | 约 430 字 |
| 译文页注譯栏 | 高 295px | 13.1px | 约 270 字 |
| 散文页 | 高 532px | 22px / 行高 2.05 | 约 **450 字** |

### 7.4 超长句兜底

竖排高度由**该页最长一句**决定。当某页出现 > 16 字的句子时，
`verse_slide()` 会按 `COL_BASE_PX * FIT_CHARS / 最长字数` 自动缩该页字号
（通过 `--col-font` 变量），保证**任何情况下不溢出**。

> 当前全书仅 1 页触发：`卷三 二十哿 第3段`（源文本有一处 17 字的可疑重复字，见 §9.4）。

### 7.5 分页不跨韵部

每个韵部**另起一页**。因此某卷的总页数 = `Σ ceil(该韵段数 / 2)`，
**不等于** `ceil(总段数 / 2)`。这是页码计算最容易错的地方。

## 8. 质检规范

**任何 deck 在交付前必须通过：**

```bash
make check          # 等价于 python3 src/check_deck.py
```

要求输出 `全部通过 ✓`（0 问题）。检查项：

| 类型 | 含义 |
|---|---|
| `out_of_slide` | 任何叶子文本元素越出幻灯片画布 |
| `text_overlap` | 任意两个叶子文本元素互相重叠（绝对定位串位、缩进跑字、封面内容与署名碰撞等） |
| `col_overflow` | 竖排列的文字高度越出舞台 |
| `stanza_overflow` | 竖排组越出舞台宽度 |
| `content_overflow` | 栏内容 `scrollHeight/Width` 超过容器 |

> `text_overlap` 是本项目**唯一由人工目视发现后补上的检查项**：
> 封面一度出现「韵目行压住页脚署名」，而 `out_of_slide` 抓不到——
> 因为两者都在画布内，只是一个在文档流、一个是绝对定位。教训是
> **"没出界"不等于"没重叠"**。

补充要求：

- **目视复核**：截图后人工（或支持图像输入的模型）确认无压字、错位、空洞。
  纯数值通过 ≠ 视觉合格——本项目已经踩过"元素盒子没问题但盒内文字跑出去"的坑
  （`text-indent` 被 `inline-block` 继承导致标签压住序号）。
- **截图留档**：`src/render_check.py` 的 `screenshot_slides()` 输出 1280×720@1.5x
  真彩图，导出时强制 `transform:none`，避免 deck 缩放引入黑边。

## 9. 内容规范（考据）

### 9.1 三条铁律

1. **严禁编造**。引文、篇名、反切、书证必须来自**实际抓取到的页面**。
2. **存疑必标**。查不到就写「未檢得」，并说明查过哪些来源；不得为好看而攀附典故。
3. **区分"用典"与"义类相对"**。例：「海嶽／雷風」只可取象相通，
   《說卦》有「山澤通氣，雷風相薄」之對待，但「海嶽」非《說卦》原詞，
   唐宋詩中「海嶽」皆作宇內山川義——故判为**义类工对**，不写作"用《說卦》典"。

### 9.2 引文体例

- 繁体中文；引文用「」逐字抄录，不改写、不节略后不加说明。
- 每条注明出处（书名·篇名），必要时附卷次。
- 辨正类内容单独标注：以 `<span class="src">辨正：…</span>` 呈现。

### 9.3 检索环境（重要）

- **`web_fetch` 工具在本机不可用**：DNS 走 fake-IP（198.18.x），触发 SSRF 拦截。
  一律改用 `bash` + `curl`：
  ```bash
  curl -sSL --max-time 25 -A "Mozilla/5.0 ... Chrome/124.0 Safari/537.36" "URL"
  ```
- **ctext.org 不可用**：Cloudflare 拦截且声明会"故意返回损坏数据"，一律不采用。
- 可用：`zh.wikisource.org`（`action=raw` / MediaWiki `insource:` 全文检索，最稳）、
  `zdic.net`（汉典，反切与书证）、`shidianguji.com`（识典古籍）、
  `dict.revised.moe.edu.tw`（教育部辞典）。
- 考据抓取的原文缓存统一放 `research/原文緩存/`，便于复核。

### 9.4 校勘

**任何对原文的改动都必须登记在 `docs/校勘記.md`**，并满足：

- 一句一议，写明位置（卷·韵·段·行 + slide id）、原作、校改、依据。
- 依据须**多条互证**（句式／用字／押韵／对仗至少两条），不得凭语感改字。
- **无法确证的字一律不动**，原样保留并登记待办
  （例：作者自用的部件记字 `「艹項」`、`「山畾」`、`<禾夅>`）。

已校改 1 处、待办 3 处，详见 **[校勘記.md](校勘記.md)**。
